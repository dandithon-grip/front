# 샛길

출퇴근·등하교 동선에서 자연을 만나는 모바일 웹 프런트엔드입니다. Figma 화면을 바탕으로 경로 설정, 오늘의 추천, 경로 비교, 평가와 풍경 기록을 연결했습니다.

실제 서비스 API를 사용하는 모드와 **사용자가 직접 선택하는 예시 미리보기**를 구분합니다. API 연결 실패를 샘플 성공으로 자동 대체하지 않습니다.

## 실행

Node.js **22 이상**과 npm이 필요합니다. 고정된 Supabase 클라이언트의 Node 요구사항을 따릅니다.

```bash
git clone https://github.com/dandithon-grip/front.git
cd front
npm ci
cp .env.example .env.local
npm run dev
```

개발 서버는 [http://localhost:3000](http://localhost:3000)에서 실행됩니다. 3000 포트를 사용 중이면 서버가 오류로 종료하므로 기존 프로세스를 확인해 주세요. 현재 확인된 운영 CORS 설정은 `localhost:3000`을 허용합니다.

인증 키를 넣지 않아도 로그인 화면의 **예시로 둘러보기**로 샘플 흐름을 확인할 수 있습니다. 지도는 Kakao 설정이 없으면 OpenStreetMap 배경 지도에 경로를 표시합니다. **로그인 없이 둘러보기**는 운영 서버의 공개 데모 카드를 요청하므로 서버 상태의 영향을 받습니다.

```bash
npm run build    # TypeScript 검사와 dist/ 프로덕션 빌드
npm test         # Store, API 요청, 좌표·외부 지도 링크 테스트
npm run preview  # dist/ 로컬 확인; 표시된 포트의 CORS 설정은 별도 확인
```

테스트는 외부 서비스를 모킹해 요청 계약, 인증·계정 전환, 상태 복원, 미리보기 분리와 좌표 처리를 확인합니다. 실제 계정 로그인·업로드·푸시 수신을 성공시켰다는 의미는 아닙니다.

## 환경변수

`.env.example`을 `.env.local`로 복사한 뒤 필요한 공개 설정을 채웁니다. 환경변수를 바꾸면 개발 서버를 다시 시작하고, 배포 환경에서는 다시 빌드해야 합니다.

| 변수 | 용도 |
| --- | --- |
| `VITE_API_BASE_URL` | API 주소. 기본값은 팀 운영 Railway 서버 |
| `VITE_SUPABASE_URL` | Supabase 프로젝트 URL |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | 브라우저용 공개 클라이언트 키 |
| `VITE_KAKAO_JAVASCRIPT_KEY` | Kakao 지도·장소 검색용 JavaScript 키 |
| `VITE_ODSAY_WEB_KEY` | Notion `ODSAY_API_KEY_FE`의 ODsay URI 플랫폼용 키. localhost·배포 도메인 등록 필요 |
| `VITE_MAP_TILE_URL`, `VITE_MAP_ATTRIBUTION` | Kakao 미설정·실패 시 사용하는 배경 지도 공급자와 추가 출처 표시 |
| `VITE_SUPABASE_RECORD_BUCKET` | 사진 비공개 버킷명. 기본값 `records`, 서버 설정과 일치 필요 |
| `VITE_FIREBASE_*` | Firebase 웹 앱 공개 설정 6종과 웹 푸시 VAPID 공개키. 전체 이름은 `.env.example` 참고 |

기존 프로젝트의 공개 anon 키는 `VITE_SUPABASE_ANON_KEY`로도 읽을 수 있습니다. `VITE_` 값은 브라우저에 포함됩니다. **service role·secret key, DB 비밀번호, Firebase 서비스 계정 비공개 키는 넣지 않습니다.**

Kakao 지도는 키 입력 외에 앱의 카카오맵 사용 설정 ON, JavaScript SDK 도메인 등록이 필요합니다. 사진 업로드는 비공개 Storage 버킷과 본인 UUID 폴더의 업로드·조회 RLS가 필요합니다. 실제 프런트 배포 origin도 서버 CORS에 추가해야 합니다.

이번 로컬 작업에는 노션 앱에서 확인한 Supabase URL·공개 anon 키와 VAPID 공개키를 `.env.local`에 연결했습니다. 이 파일은 Git에서 제외되며 배포 환경변수는 별도로 등록해야 합니다. 노션의 같은 페이지에는 Kakao JavaScript 키와 Firebase 웹 앱 설정이 없었고, 사용자가 별도 설정 페이지도 없음을 확인했습니다. 서버용 Firebase 서비스 계정 JSON은 웹 앱 설정을 대신할 수 없습니다.

ODsay는 최신 백엔드 `48b9433`의 웹 계약을 사용합니다. 브라우저가 ODsay `searchPubTransPathT`를 직접 조회하고, 원본 JSON을 인증된 `POST /transit/routes/parse`의 `{ "odsay": 원본응답 }`으로 전송합니다. 기존 `GET /transit/routes`로 우회하지 않습니다. Supabase Bearer 토큰은 앱 서버에만 보내며 ODsay에는 보내지 않습니다. 후보 선택·`transit_legs` 저장 형식은 기존과 같습니다.

2026-11-08 Notion의 새 `ODSAY_API_KEY_FE`를 로컬 `.env.local`과 Vercel Production의 `VITE_ODSAY_WEB_KEY`에 연결했습니다. 실제 `http://localhost:3000`과 `https://grip-front.vercel.app` 브라우저에서 각각 HTTP 200·대중교통 후보 17개·error 없음으로 직접 조회에 성공했습니다. 기존 서버용 `ODSAY_API_KEY`의 브라우저 인증 실패는 새 FE 키로 해소됐습니다. 운영 파싱 API의 OpenAPI 등재와 무인증 POST의 정상적인 401, 개인 배포 origin의 서버 CORS 허용도 확인했습니다. 로그인 후 파싱·후보 선택·저장 전체 흐름은 별도 검증이 필요합니다.

배포 시에는 프론트 호스팅 환경에 `VITE_ODSAY_WEB_KEY`를 등록하고 다시 빌드해야 합니다. ODsay URI 허용 목록에는 `http://localhost:3000`과 실제 배포 origin을 등록합니다. 현재 개인 저장소의 배포 주소는 `https://grip-front.vercel.app`입니다. ODsay URI 허용과 앱 서버의 CORS 허용은 각각 별도 설정입니다. 키 값은 소스·문서에 커밋하지 않습니다.

설정·서버 변경 요청과 확인 방법은 [백엔드·외부 설정 의존사항](docs/backend-dependencies.md), 전달용 요청서는 [백엔드 요청사항](docs/backend-handoff.md)에 정리했습니다.

## 연결한 흐름

- **인증:** Supabase 이메일·비밀번호 가입·로그인, 세션 복원·갱신, 로그아웃, 닉네임·비밀번호 변경. 서버 요청에는 Bearer access token을 사용합니다.
- **일상 경로:** 출발지 → 도착지 → 출근 시간 → 퇴근 시간 → 교통수단의 5단계 설정. 기본 걷기 취향을 선택하고, 대중교통은 경로 후보와 탑승 구간까지 확인합니다. 실제 좌표로 동선을 저장하고 샛길 생성을 요청합니다.
- **홈·경로:** 오늘 추천 한 장과 ‘다른 길 보기’를 구분합니다. 출근·퇴근 방향, 후보·최단 경로, 선택한 경로 ID와 실제 시간·녹지율을 사용합니다. 취향은 `full`(자연 가득), `short`(짧게 걷기), `sunset`(노을길)에 대응합니다.
- **지도·걷기:** 앱 안에서 Kakao 또는 OpenStreetMap 배경 지도에 API 경로를 표시합니다. 걷기 시작 시 브라우저 위치 권한을 요청하고 현재 위치·정확도·따라가기·남은 거리·진행률·추정 남은 시간을 표시합니다. 일시정지·다시 시작·종료가 가능하고, 연속된 정확한 위치로 도착을 확인합니다. 위치 오차·경로 이탈·오래된 위치·비정상 이동을 구분하며, 위치 이력은 서버에 보내지 않습니다. 화면이 숨겨지면 위치 추적을 멈추고 복귀 후 다시 시작합니다. 외부 카카오맵 링크는 보조 기능이며, 회전별 지시와 자동 재탐색은 제공하지 않습니다.
- **퇴근 알림:** Firebase 웹 푸시 권한 요청, 기기 등록·해제, 테스트 전송, 앱 안 수신 배너와 백그라운드 서비스워커를 연결했습니다. 서버에 등록된 뒤에만 켜짐으로 표시합니다. 로그아웃 전 등록 해제, 다른 탭의 계정 변경 후 기기 토큰 정리도 처리합니다. 현재 서버 지원 범위인 퇴근 10분 전 알림 하나를 사용하며 설정·지원·권한·운영 API 오류를 구분합니다.
- **평가·취향:** 정수 별점 1~5를 저장한 뒤 완료를 표시합니다. 누적 태그 가중치를 조회·초기화합니다. 초기화는 과거 평가와 기본 취향을 지우지 않습니다.
- **풍경 기록:** 사진을 재인코딩해 위치 메타데이터를 제거한 후 Storage 업로드 → 선택적 AI 계절·상태 제안 → 사용자 확인 → 기록 저장으로 연결합니다. 목록은 실제 개수와 계절 현상 필터를 사용하고 장소별·연도별로 볼 수 있습니다. 사진 저장에는 로그인, 사진, 유효한 장소 ID가 필요합니다.

게스트는 공개 데모 조회만 사용할 수 있습니다. 개인 취향 적용, 출근 방향, 평가·기록 저장 등은 로그인으로 안내합니다.

## 예시 미리보기와 저장

**예시로 둘러보기**는 실제 인증·경로 계산·계정 저장 없이 흐름을 확인하는 별도 모드입니다. 관련 화면에 미리보기 표시가 나타납니다.

예시의 초록색 선은 출발·중간·도착 좌표를 연결한 화면 확인용 도형입니다. 실제 도로를 따라 계산한 보행 경로가 아닙니다. 배경 지도가 실제여도 예시 경로·시간·녹지율은 실제 추천 결과가 아니며, 예시 모드의 GPS 거리·진행률 역시 이 연결선 기준입니다. 실제 안내에는 서버가 계산한 도로 경로의 `polyline`이 필요합니다.

- 예시 동선·선택·평가·취향·기록은 `saetgil:preview:v2` 캐시에 저장됩니다. 계정 데이터와 합치지 않습니다.
- 실제 세션은 Supabase SDK의 `saetgil:auth:v1` 저장소를 사용합니다. 브라우저의 로컬 로그인 표시를 인증 근거로 사용하지 않습니다.
- 실제 동선은 서버 DB에 저장하고, 실제 사진은 비공개 Storage에 업로드합니다. ‘위치는 이 기기에만 저장’하는 구조가 아닙니다.
- 미리보기 사진 캐시는 브라우저 용량의 영향을 받습니다. 계정에 영속 저장된 사진으로 간주하지 않습니다.

## 남은 의존사항과 검증 범위

Supabase 공개 설정의 정상 응답과 실제 로그인 실패 처리는 검증했습니다. **운영 계정 로그인부터 실제 사진 업로드까지의 E2E는 아직 검증하지 않았습니다.** 기존 테스트 계정, 버킷 정책과 정상 운영 서버가 필요합니다. 위치 추적은 HTTPS(로컬에서는 localhost)와 사용자 권한이 필요하며 실제 기기의 이동 정확도는 별도 확인해야 합니다.

- 2026-11-08 재확인에서 운영 데모 카드는 **200**으로 정상화됐고 푸시 API도 운영 명세에 반영됐습니다. 브라우저의 ‘로그인 없이 둘러보기’로 실제 추천 3개·최단 도보 구간 2개를 조회하고, 선택한 101점·약 1.6km의 도로 경로가 앱 지도에 표시되는 것을 확인했습니다. 이 경로에서 모의 GPS로 진행률·남은 거리·일시정지도 검증했습니다. 앞선 데모 500·푸시 명세 누락은 이전 관측입니다.
- FCM 프런트 구독 코드와 운영 API 명세는 준비됐지만 **Firebase 웹 앱 설정이 없어 실제 기기 등록·수신은 미검증**입니다. 설정이 없을 때 권한 요청이나 가짜 구독 성공을 표시하지 않습니다.
- Kakao 전용 장소 검색에는 JavaScript 키·사용 설정·도메인이 필요합니다. 키가 없으면 실제 정류장 검색과 지도에서 좌표 선택을 사용할 수 있습니다.
- **15종 취향 직접 선택 저장은 미지원**입니다. 서버는 기본 취향 3종과 별점 기반 가중치의 조회·초기화만 지원합니다. ‘조용한 길’을 ‘짧게 걷기’로 임의 매핑하지 않습니다.
- **장소 상세 메타데이터 API가 없습니다.** 실제 기록 장소는 경로가 제공한 UUID를 사용하고, 이름이 없으면 자연 장소 순서로 표시합니다. 고정 장소명을 실제 결과로 붙이지 않습니다.
- **계절 소개는 정적 읽을거리**입니다. 실시간 절기·날씨·장소별 자연 상태 데이터가 연결된 것으로 표현하지 않습니다.
- **무사진 방문 기록은 미지원**입니다. 현재 서버 기록 계약은 사진 경로와 계절·단계가 필수입니다.
- AI 제안 후 저장을 취소하는 등의 경우 생길 수 있는 **미참조 업로드 파일 정리**는 운영 후속 작업입니다.

기본 OpenStreetMap 타일은 가시적인 출처 표시와 일반 브라우저 캐시를 사용하며 오프라인 다운로드·사전 수집을 하지 않습니다. [OSM 타일 이용 정책](https://operations.osmfoundation.org/policies/tiles/)에 따라 대규모 서비스 운영 시 적합한 지도 공급자를 지정해야 합니다. `VITE_MAP_TILE_URL`과 `VITE_MAP_ATTRIBUTION`으로 공급자를 바꿀 수 있습니다.

구체적인 서버 계약, 설정 이름, 실제 점검 결과와 완료 기준은 [별도 문서](docs/backend-dependencies.md)를 기준으로 확인해 주세요.

| `/route-setup` | 단계별 일상 경로 설정 |
| `/home`, `/season` | 오늘의 샛길·계절 이야기 |
| `/route`, `/routes` | 지도·경로 비교 목록 |
| `/guide`, `/rating` | 선택 경로 안내·별점 |
| `/photo` | 사진 기록 작성 |
| `/record`, `/record/:placeId` | 전체 기록·장소별 연도 기록 |
| `/my`, `/my/edit` | 내 정보·계정 수정 |
| `/my/route`, `/my/preferences` | 동선 수정·누적 취향 |

## 배포

정적 빌드 결과는 `dist/`입니다. Vercel에서는 저장소의 `vercel.json`이 SPA 경로를 `index.html`로 재작성해 직접 주소 진입·새로고침을 처리합니다. 다른 호스팅도 같은 SPA fallback 설정이 필요합니다.

배포 환경에 공개 환경변수를 등록하고 빌드한 뒤, 실제 HTTPS origin을 서버 CORS와 Kakao JavaScript SDK 도메인에 등록합니다. `npm run preview`는 로컬 빌드 확인 명령이며 운영 배포가 아닙니다.

## 기술·파일 구성

React 18, TypeScript, Vite 5, React Router 6, Supabase JS를 사용합니다. 스타일은 일반 CSS, 폰트는 Pretendard와 Cafe24 Ssurround입니다.

